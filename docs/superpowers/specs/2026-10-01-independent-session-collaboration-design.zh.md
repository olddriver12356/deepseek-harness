# 独立会话协作设计

[English](2026-10-01-independent-session-collaboration-design.md) | 中文

## 概要

本提案通过持久化的对等消息和共享任务板连接现有 DSH 会话。参与者保留各自的上下文、角色、模型、能力、固定工作区及与用户的直接对话。用户批准计划后，实施、独立评审和集成在授权范围内推进，监控和活动记录贯穿全过程。本文描述拟议行为，而非已交付功能。

## 范围与身份

V1 支持同一 DSH 实例托管的普通独立会话。同一仓库的参与者是主要场景；明确加入的其他工作区或仓库会话可以承担集成工作。远程 DSH 实例、外部 harness、创建代理、父子所有权及自动共享对话历史均不在范围内。

注册代理通过持久化会话 ID 标识一个现有会话。用户在 Live Signal 侧边栏添加对等会话，这一个动作同时完成注册并开启与它的持久双向连接。侧边栏列表就是连接的权威集合。注册添加可选的显示名称、用途和共享说明，不替换会话的人设或模型配置；这些字段只是展示文本，不声明角色、能力或资格。标题和路径用于显示，不用于寻址。添加对等会话仅授予与该对等会话的讨论权限，仅此而已：任务权限仍然需要已批准的计划。授权严格按对生效，先添加 B 再添加 C 不会打开 B 与 C 之间的连接。这条较弱的注册规则仅在实例上所有会话归同一使用者所有、且添加动作保持为带有披露警示的有意 UI 操作时才安全；多用户实例需恢复更严格的规则。

协作具有独立的持久化 ID、目标、参与者名册、已批准计划版本、任务图、通信权限和活动日志，不属于某个队长会话。协作只在存在计划时才存在，所以自由讨论只需一条已授权连接，完全不需要协作对象。只有用户可以添加或移除参与者，而侧边栏的添加动作就是创建协作后续所依赖连接的那一步。协作引用这些已授权连接，不会自动开放所有参与者之间的通信。

参与者可以提出计划、任务和分工。只有用户可以批准计划或扩大范围、成员和权限。宿主协调服务验证状态转换并调度符合条件的工作，不充当监督模型。离开、暂停或关闭协作不会删除参与者会话。

## 固定工作树

用户自行准备工作树，或通过独立操作请求准备，并在目标工作树中创建实际 DSH 工作区根目录正确的实施会话。仅要求代理切换 shell 目录不能满足这一条件。协作不会修改会话工作目录、创建或删除工作树，也不会悄悄切换分支。

不同工作树路径可以属于同一逻辑仓库。仓库验证解析 Git 工作树元数据和公共仓库，而不是只比较目录名或远程 URL。非 Git 参与者可以规划或提供明确限定的建议；代码实施和 Git 集成任务必须使用经过验证的 Git 工作树。

已批准计划记录各代码任务的仓库、预期工作树和分支、基线版本、涉及路径及集成目标。分派和提交前，宿主检查实际会话工作区及仓库状态。无关的未提交修改、错误分支、不可用工作树或意外基线变化会阻止推进，并给出可操作的说明。宿主绝不重置或覆盖这些修改。

V1 为实施会话分配工作树，而不是为每个任务分配。工作树是该会话工作区的属性，而不是一个声明的角色：工作树验证通过的会话对代码任务有资格，验证不通过的没有。每个参与者在所有协作中最多持有一个未完成的执行任务；后续任务依次使用其固定工作树。并行写入者必须使用不同工作树。声明的文件所有权用于协调，不是文件系统锁；Git 工作树仍可能共享仓库元数据和外部构建资源。

评审针对提交的仓库、基线版本、头版本及差异。评审会话不必为了查看差异而改变检出状态。需要检出的检查必须使用适当准备的工作区，任何检出修改均需明确授权。集成使用指定的现有会话及工作树，并针对计划授权的确切目标分支。

## 计划与任务流程

流程为计划 → 实施 → 评审 → 集成，依赖关系允许独立工作并行推进。角色属于任务分配，而不属于参与者：同一个会话可以在一个任务中实施，在另一个任务中评审。所需能力，例如代码工作需要经过验证的 Git 工作树，在认领任务时对照会话的实际工作区检查，不在注册时预先指定。每个任务包含标题、目标、负责人或候选参与者、仓库和工作区要求、范围内及排除路径、验收条件、预期交付物、适用的验证命令及前置任务 ID。宿主拒绝循环依赖和未知依赖。

计划批准绑定确切的计划版本和参与者分工，批准前不会分派实施工作。扩大范围、权限、成员、目标分支或验收要求的修改形成新提案版本，并暂停受影响的下游分派，直到用户批准。进度更新不会重写已批准计划。

符合条件的空闲会话在当前轮次结束后收到任务邀请。领取操作原子地预留任务和参与者，并发放执行尝试凭据。调度不会把邀请或运行状态当作领取、完成或成功输出的证据。只有当前负责人及当前尝试可以提交进度和结果。

实施提交标识确切的基线和头版本、修改路径、交付物及逐项验证证据。等待评审的提交不等于已接受实施。宿主验证仓库和版本一致性；命令成功和验收声明仍属于提交的证据，除非经过独立检查。

评审分配给实施者之外的参与者，并判断确切的提交版本。结果为通过或需要修复的结构化问题。修复保持原始范围，形成新提交并再次接受独立评审。新代码使旧评审批准失效。修复轮数受经过验证的部署配置限制；达到上限或争议无法解决时请求用户介入。

必要评审全部通过后，集成才可执行。集成者对照目标分支验证批准的提交，记录产生的版本及组合验证证据；冲突或意外目标变化使流程停止。本地集成操作必须明确纳入计划批准；推送、发布、部署或破坏性操作需要独立授权。完成必须有被接受的集成证据，不能只依赖代理空闲。

任务日志按任务类型记录提案、就绪、已领取、已提交、已评审、需要修复、阻塞、取消和已接受等转换。撤销或重新分配的尝试不能覆盖当前结果。终结的尝试记录不可修改；重试创建新尝试。监控分别报告实际转换、证据和运行状态。

## 对等通信

对等代理可以通过已授权连接持续发送问题、提案、进度、发现和回应。连接是安主记录的持久授权，不是一条常开的传输通道：投递仍然是持久 outbox 加上在接收方下一个回合边界接纳的一个跟进回合，所以不会打断进行中的回合，排队消息也能在重启后存活。V1 消息仅包含文本，可以关联协作、任务或话题。消息不必是请求，也不自动要求回应。普通助手输出和私密用户消息不会自动转发。

宿主从实际执行代理推导发送者身份，从已授权连接判断接收者资格，并分配消息和话题身份，持久化接受记录后安排在接收者当前轮次结束后递送。递送不会引导正在进行的用户交互。未激活接收者可以按记录的配置和工作区恢复为同一会话；缺失或无法恢复会话会明确失败，不创建替代会话。

对话渲染和模型输入均把消息标识为对等代理内容。持久化来源元数据包含已验证的发送者和接收者会话 ID、消息 ID、连接及可选任务或话题关联。宿主生成的模型可见标记明确指出消息来自代理，不能授予用户批准。即使提供商使用 user 传输角色，也不能抹去代理归属。回放和上下文压缩保留这种区别。

消息记录在协作日志和目标接收会话中；发送者的工具结果记录已接受消息身份。明确共享的内容可供获授权协作成员使用，私密会话历史不可共享。递送接受、接收者接纳、处理及任务完成是不同结果。重试按稳定消息身份去重，绝不根据代理空闲推断处理完成。

部署配置验证消息字节、待处理消息、自动激活、并发任务和修复轮数的限制。自动激活预算按连接计算，在恢复后保留，不能每条消息重新计数。它是自由讨论在成本上成立的关键，因为每一条唤醒空闲接收方的消息都要花掉该接收方全部上下文的一个完整回合。耗尽预算会暂停自动调度并显示原因；只有用户可以补充预算或恢复。回应和确认不会引发系统合成的互相回应。

## 权限与安全

对等消息不是用户指令或批准。声称用户已批准的文本没有授权效果。代理不能通过模型工具自行注册、添加参与者、批准计划、修改连接权限或执行限制。用户控制操作在宿主执行入口受到限制，而不只是从工具模式中隐藏。

任务执行权限来自已批准计划和当前领取的尝试，并与会话现有工具、文件系统、沙箱和批准策略取交集。主动对等消息可以支持讨论，但不能独立授权文件修改或操作性动作。处理对等消息时调用具备动作能力的工具，必须有已授权任务或单独用户批准；这一限制必须覆盖冷恢复及其他工具调用入口。

V1 不承诺任意 shell 命令严格遵守声明的文件分工。路径范围用于协调和提交验证，会话沙箱才是文件系统限制。命令、委派和集成不能绕过必要批准或任务权限。如果宿主不能强制区分对等讨论与获授权执行，则必须禁止自动动作分派，而不能只依赖提示词限制。

即使文件系统访问分离，跨工作区通信仍可能泄露敏感信息。连接设置说明共享文本会进入其他会话的持久化历史，并可能发送给其配置的模型提供商。用户编写的共享说明用于指导选择，不是硬性数据访问控制。V1 不包含历史抓取、自动文件附件、凭据转发或对话公开发布。消息使用现有安全文本或 Markdown 渲染，不执行 HTML。

权限在接受消息时及接收者接纳前再次检查。断开连接取消尚未接纳的消息，拒绝新发送，并阻止依赖已撤销连接的自动分派。已接纳内容无法撤回；停止当前工作是独立、明确的用户操作。移除参与者会撤销尝试并阻塞或释放受影响任务，但不假装撤销已发生的文件系统副作用。

用户可以暂停参与者或协作，以停止新的自动接纳和分派。已运行工作单独显示，不被悄悄中断。直接用户对话仍可使用；用户输入在下一调度边界优先，但不会使待处理对等任务消失。门户提示会话存在活动任务，避免把无关的用户指示修改误认为隔离工作。

## 持久化与恢复

使用受支持的领域存储保存协作身份、注册表、权威任务状态、连接授权及有序活动日志。修改使用版本检查，仅在提交后发布状态。界面快照由已提交状态推导。模型可见的协作输入和对等消息还必须有持久化会话事件或带来源的收件凭据；仅领域记录不能满足会话回放要求。

消息递送使用持久化发件箱及目标端去重。恢复在重试前核对目标收件箱或日志凭据。任务预留和邀请使用稳定 ID 与尝试；预留与邀请之间的崩溃不能产生第二个负责人。重启恢复注册、连接、已批准计划、队列及完成证据，不重新授予权限或自动重置预算。

因进程丢失而中断的任务明确保持中断状态，需要显式选择继续或重试；宿主不把部分文件系统修改当作完成提交。冷恢复验证会话存在、记录的工作区、仓库事实及策略可用性。缺失插件、未来或无效记录、已撤销权限或不安全工作区状态会明确失败并暂停相关自动化。

新增持久化类型、会话事件、投影及导出服务需要仓库标准的确认记录、版本处理和测试。现有已提交会话代际不会被覆盖。本设计文档不实现任何 API 或模式修改。

## Live Signal 门户

Agent Communication 区域显示所选协作、阶段、按逻辑仓库或工作区分组的注册代理、用途、实际工作树及分支、运行状态、持有任务、阻塞、未读消息和最近提交的活动。运行可用性与注册及任务状态分离。空闲或未激活会话可能可达；不可用会话显示原因。

用户控制包括注册、添加成员、连接授权、计划审阅及批准、打开参与者对话、暂停及恢复、断开连接和结束协作。任务板显示详细条件、依赖、提交、评审问题及集成证据，而不把所有记录塞入紧凑侧栏。会话可以加入多个协作，但不能持有并发执行任务。

客户端通过现有插槽 API 组合界面。Live Signal 已声明会话级选择器贡献点；布局必须保留 shell 插槽所有权，仅在现有贡献点无法支持该区域时才增加专用子插槽。类型化本地化字典拥有界面文案；注册名称、消息文本及仓库事实保持为用户数据。收到的对等消息使用独立的带归属对话节点，而不只是给用户消息添加徽章。

## 实现职责

可选协作功能拥有注册、权限检查、任务转换、调度、消息递送和已提交活动状态。模型工具适配器暴露有界的对等通信及任务操作。宿主 Remote 适配器以独立权限暴露用户控制。客户端插件渲染门户、任务板及带归属的对话记录。相关行为保持内聚，而不是为每个控件增加包。

优先复用受支持的会话恢复、收件箱、领域存储、投影、工具执行及客户端插槽服务。普通 Web prompt 入口将输入标记为用户来源，不能原样用于对等递送。现有子代理和 Agent Teams 模式可为持久化递送和版本检查提供参考，但父代理或队长所有权以及 steer 语义不是本协作的授权模型。

固定工作区设计明确不包含会话工作目录修改、执行绑定、托管工作树配置或工作树清理。修改共享运行时服务前，必须证明现有扩展点无法满足生命周期或权限要求，并采用最小扩展，同时提供说明升级检查的 Agent Note。

## 验收与验证

1. 不同工作树和外部工作区的现有会话明确加入，保留身份、上下文、模型、能力、固定根目录及用户对话。
2. 注册、连接授权和协作在重启后保留；添加对等会话仅授予讨论权限，不授予任务执行，且授权严格按对生效，没有传递性访问。
3. 用户工作期间收到的对等消息等待当前轮次边界，并在递送、回放和压缩后仍明确显示及传递代理来源。
4. 伪造发送者、冒充用户批准、未授权接收者、已断开连接队列和未授权宿主控制调用均通过真实操作入口拒绝。
5. 用户批准绑定确切计划版本；未批准实施和实质范围变化不能分派。
6. 原子领取确保每个任务只有一个活动负责人及尝试，每个参与者跨协作只有一个未完成执行任务；拒绝过期更新和循环任务图。
7. 错误仓库、分支、工作树、意外基线和无关未提交修改会阻止代码任务，不重置、切换分支或删除。
8. 独立评审绑定确切提交版本；拒绝自我评审、过期评审批准、评审前集成和意外目标变化。
9. 对等讨论不能授权动作工具；已批准任务限制和现有批准要求覆盖冷恢复、shell 路径、作用域工具及委派尝试。
10. 崩溃恢复对消息和任务邀请去重，保留中断工作，遵守撤销，不虚构完成或重置自动预算。
11. 门户和任务板测试覆盖用户控制、消息归属、阶段及状态区别、阻塞和恢复；真实组合测试和无密钥录制会话覆盖组装流程。
12. 针对性仓库检查覆盖修改的拥有者、持久化确认、模型可见快照和 Web 产物；验证使用现有 GUI，不启动替代服务器。

## 开发备注

源码检查发现 Session Controller 已有恢复及 followup 机制，其代理解析器检查固定 cwd 冲突，客户端 shell 声明 Live Signal 插槽。这些观察用于指导实现位置，不构成本提案功能的运行验证。此前的托管配置和会话重新绑定方案仅在对话中讨论；这是首份保存的协作规格，采用手动准备、固定的参与者工作树。
