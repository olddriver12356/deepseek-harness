# Agent Note: 独立会话协作

Status: proposed

[English](2026-10-01-independent-session-collaboration.md) | 中文

## 问题

独立创建的会话需要持久的讨论连接，同时不能改变工作区，也不能把对等消息当成人类指令。现有经过身份验证的 UI 传输无法对与模型拥有的进程使用同一操作系统用户的调用方建立人类专属执行授权。动态 Host 代码也仍可访问 Host realm 的函数。因此，讨论授权与执行授权需要不同的保证。

## 提案

组合一个可选的 Host 插件，提供持久的成对连接、人类 UI 控制、明确的对等来源标识，以及 `collaboration_status` 和 `peer_send` 两个模型工具。V1a 只支持讨论。在 Prerequisite P 提供可强制实施的人类专属执行准入之前，任务派发、领取、执行批准、审查和集成继续延后。[设计](../../../../docs/superpowers/specs/2026-10-01-independent-session-collaboration-design.zh.md)描述完整功能；V1a 是仅讨论的里程碑。

当前策略里程碑为讨论控制使用模块私有的对象能力。工具 JSON 和克隆对象无法重建它；任意 Host 代码和同一用户通过身份验证的 Gateway 请求不在此保证范围内。构造函数不在包入口和模型工具注册表中。讨论 Remote 适配器使用现有的经过身份验证的 Connection/Gateway 传输，在内部创建准入。它不接受 JSON 能力标记，也不通过该路径授予执行权限。

回合权限归实际执行的 Agent（智能体）所有。唯一的分类是 `human` 和 `peer-discussion`。对等和未知来源的输入使回合更严格；受支持的工具与插件上下文是中性的。`tools.guard` 在可扩展的执行前策略之后拒绝对等执行工具。配置只能选择已审查的 `read`、`glob`、`grep`、`collaboration_status` 和 `peer_send` 名称；不能仅通过添加名称准入任意能力。这使用已有运行时扩展点，不改变共享运行时的负责模块。

对等消息传递必须在准入输入之前要求已安装协作权限，冷接收方也不例外。`requireCollaborationAuthority(ctx)` 提供此存在性检查，并随策略注册一起移除。消息传递与接收方解析模块还必须在对受保护的对等工作默认拒绝的同时，保留普通人类会话的恢复行为。当前全局安装函数把每个未分类的 Agent 默认视为讨论；它自身并不解析这种区别。

持久化里程碑在版本 1 的 domain `collaboration`、table `state`、record `current` 中保存 V1a 注册信息、会话对、outbox 消息、预算、journal 条目和 actor 隔离的原始请求回执。`KvTable.update` 在持久写入后原子发布完整聚合记录和有序 journal；它以重写保留数据为代价，避免跨记录权限归属和 outbox 竞态。明确验证的容量限制会停止写入，而不会丢弃权限或待处理工作。仅供任务使用的 schema 继续延后。排队消息的 `activationReserved` 事实与预算扣减一起提交；持久的接收方接受是独立的 `admitted` 迁移，因此断开连接仍可取消已预留的排队工作，而不虚报接收方输入状态。

Remote 里程碑通过存储的 Session header 观察派生普通会话身份和 cwd，不唤醒 Agent，也不读取对话事件。人类显示标题是明确输入；允许普通 fork 和不同工作区。首次连接在一次事务中注册两个端点并授权会话对。系统在生成新的 Host 身份或元数据前检查原始请求意图，因此后续 header 改变也不会破坏重试。snapshot/follow 只返回已授权的成对记录。完整 revision 快照允许重连和缺口恢复，每条流只保存一个待发布视图；即使直接消费者停止拉取，dispose 也会移除监听器。

## 已考虑的替代方案

**把 UI 凭据用作执行授权。** 永久调查测试表明，同一用户的 shell 可以使用测试自有的本地凭据完成身份验证，动态 VM helper 也可以访问 Host 进程。另一个环境 token 或隐藏方法无法区分人类与这些调用方，因此不能解除执行派发的阻塞。

**让配置准入任意工具名称。** 这允许普通的允许列表编辑把 `write` 或动态执行权限授予对等消息。采用经过审查的封闭集合，由配置缩小并在安装时复制，可以保留仅讨论的保证。

**让每个恢复的会话都必须具备全局核心策略。** 普通会话在没有此可选功能时仍应受支持。受保护接收方的发现和冷对等准入属于协作消息传递模块；修改核心运行时会给人类会话施加无关要求。

**分别持久保存每项授权、消息和预算。** 现有 storage-domain 原语会串行执行记录更新，但不提供多记录事务。分别写入可能提交 outbox 却没有扣减预算，或只撤销会话对的部分状态。一个聚合记录在无需添加数据库的前提下保持这些迁移原子化；有界保留仍是明确的操作成本。

## 验收标准

策略里程碑通过真实 Loader/Include 服务加载测试自有的 `cordis.yml`，使用生产环境的 AgentLoop、工具执行器、会话存储和 JSONL 后端。它拒绝伪造的讨论准入、不安全配置、对等写入、shell/动态/委派/发布调用，以及监听器撤销限制的尝试。测试独立验证文件和持久日志，恢复中断的工作，拒绝失败的恢复发布，并在清理期间等待请求取消。永久的同一用户 Gateway 和动态 VM 测试记录当前仍被准入的攻击。

持久化里程碑验证陈旧并发写入、存储发布失败、每对会话授权、预算预留与断开连接、actor 隔离的重试结果、损坏记录、明确容量限制和 dispose。使用生产 JSON backend 的真实 Loader 组合验证磁盘状态、重启和插件重新挂载不会补充预算。

Remote 里程碑通过安装生产 Connection/Gateway、JSON 存储和 JSONL Session header 的 Loader 组合验证已认证变更和流。未认证调用和伪造的 JSON 准入会失败。元数据浏览不需要 Agent 服务。测试覆盖并发重试、陈旧 revision、成对过滤、保留已准入工作的排队取消、流重连和卸载/重新挂载。直接 Host 执行和同一用户的已认证请求仍是已记录的限制，而不是被拒绝的攻击。

完成 V1a 还需要明确的对等来源日志和接收记录解析、缺少策略时拒绝冷接收方、普通人类会话恢复、模型工具、Live Signal 入口，以及通过最终可选组合运行的不依赖 API 密钥的录制会话场景。测试夹具不会启用任何发布默认配置或真实会话。

## 风险

执行器策略要求调用方携带实际 Agent。任意 Host 代码可以直接调用服务或省略该身份；此插件不是进程沙箱。已安装策略标记证明的是存在性，并不隔离 Host 代码。在解析器实施接收方范围和已安装策略检查之前，生产环境消息传递仍不可用。已有沙箱、批准和工具策略继续生效。解除 Prerequisite P 是任何未来执行权限能力的独立前置条件。
