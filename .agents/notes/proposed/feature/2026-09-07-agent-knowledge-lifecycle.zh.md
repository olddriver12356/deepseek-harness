# Agent Note: Agent Knowledge lifecycle

Status: proposed

[English](2026-09-07-agent-knowledge-lifecycle.md) | 中文

## 问题

DSH 对话包含有用证据，但保存对话不等于知识已验证，也不等于获准发布到用户 Vault。

## 提案

DSH 材料保留在 Agents 内。已提交对话记录与清理后的 News 摘要以确定性方式保存在 Intake。明确请求 AI 处理时创建独立的 Processed 卡片，保留来源证据。主标签暴露 Intake、Processed 和 Knowledge · To learn；Methods 保留独立的执行控制。直接概念问题进入未审阅、未学会的 Knowledge，不额外创建 Intake 副本。用户接受、学习和发布到 Agents 之外是独立决策。

[Host Knowledge](../../../../packages/host/knowledge/README.zh.md) 和 [Client Knowledge](../../../../packages/client/ui-knowledge/README.zh.md) 的实现支持保存、隔离且无工具的处理、保留失败执行及重试、绑定修订的审阅和学习、搁置和单独批准的发布。发布仅创建新文件，后续版本需要新文件名和重新批准，不覆盖用户编辑。原始证据保持完整。本地 Host 已启用；真实模型处理和最终发布的完整用户验收仍待完成。

## 考虑过的替代方案

阅读器沿用 Boujoy 的卡片直接打开模态窗口交互、黑色标题栏和手机底部抽屉，Vault 操作保留在正文下方。用户要求把原版奶油色阅读面改为深炭灰，并同步调整文字和控件对比度。加载状态和读取错误保持可见。原件与派生条目使用规范 `derivedFrom` 标识及本地返回栈导航。现有安全 Markdown 组件渲染产物与对话正文，不执行来源 HTML；原始产物和完整证据默认折叠，避免存储语法占据阅读界面。此呈现不请求模型，不改变保存证据或审批要求。

**Agent 直接发布：**拒绝，因为生成材料可能未经批准就进入用户整理过的知识。

**移动同一份来源 package：**不用于对话保存，因为蒸馏不能替换原始证据。

## 验收标准

新闻卡片提供显式蒸馏操作，先保存 feed 证据，再调用隔离处理。加载期间禁止重复点击，失败可重试。可选 Knowledge 通过 Cordis 服务查询读取，缺失时不会导致 News 覆盖层崩溃。应用排版采用 usage-stats 插件筛选器的 14px 下限，覆盖源 CSS、共享文字变量和图表标签，更大的文字保留层级。CSS 审计脚本和浏览器计算样式检查验证该下限，不使用 MutationObserver 或运行时文字缩放循环。已安装插件的样式位于应用源码树之外，因此其控件需要局部主题覆盖。

保存保留完整的已提交记录，不调用 AI，并对相同证据去重。处理具有持久的进度、失败和重试状态，不接收工具、工作区指令、Memory、MCP 或 agent 组装。结构化输出和建议的已有目录均经过验证。审阅使用最小状态标记和当前修订，不使用旧验证回执。发布要求 Knowledge 已学会、目标位置与内容预览以及明确批准。测试以假模型覆盖组装后的 Host、安全路径、共享写入、来源完整性与 UI 错误；真实模型输出质量和用户发布验收仍需人工检查。

## 风险

保存切片保留附件引用而非附件字节。对话投影展示已提交的用户与助手正文，不重放工具或注入上下文；完整证据仅在请求时加载。生命周期状态由规范产物管理，不另建 UI 数据库。清理外部文本不能证明不存在提示词注入；来源文本在审阅后仍是数据。多卡写入不是原子事务，失败后可能留下部分未审阅产物。发布中断可能留下不完整的新笔记，重试拒绝覆盖。Resources 中已有的 News 文件不迁移。
