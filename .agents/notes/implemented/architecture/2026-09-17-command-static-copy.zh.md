# Agent Note：静态命令贡献文案

Status: implemented

[English](2026-09-17-command-static-copy.md) | 中文

## 问题

已安装的订阅插件用字符串说明注册 `/fast`。命令菜单将所有说明作为回调调用，在返回任何宿主命令或客户端贡献项之前抛错。context 和技能等独立触发源仍能出现，掩盖了局部失败。

## 决策

CommandContribution 的 label 和 description 同时接受字符串与回调。生成候选项时，每次执行回调，静态文案直接传递。所有贡献项共用这条路径；宿主命令重名检查与可用性规则保持不变。

## 考虑过的替代方案

修改已安装的订阅插件构建文件会被包更新覆盖，也无法修复其他使用字符串的贡献项。静默省略失败的贡献项会隐藏其命令。同时支持两种文案表示方式，可以保留已安装插件的行为，无需停用订阅供应商。

## 后果

第一方本地化贡献项继续使用回调。静态插件文案直到拥有者重新注册时才会变化。其他错误回调仍会报告异常；这项兼容改动不吞掉任意插件故障。

## 测试

回归测试用静态标题和说明与宿主命令并存的场景复现故障。已有测试继续覆盖回调本地化、派发与卸载。相关服务及浏览器插件测试共 71 项通过。静态字符串只能在拥有者重新注册文案后切换语言，因此第一方本地化贡献项继续使用回调。本改动不修复其他供应商 RPC 兼容性问题。
