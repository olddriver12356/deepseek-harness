# Agent Note: About Me 内的 Vault Memory

Status: implemented

[English](2026-09-20-vault-memory-view.md) | 中文

## 决策

用户要求在 About Me 内增加 Memory 视图并使用提供的背景，不增加应用入口。现有 `ui-personal` 插件负责内部视图和经过认证的只读 API。打开 Memory 时原 iframe 保持挂载，保留 Personal Core 中尚未保存的状态。未改动固定版本的 Bok 代码或共享运行时服务。

视图通过 `ideasVaultRoot` 读取用户 Vault，而非 Bok 的私有运行时 Vault。Working、Episodic、Semantic 和 Handoff 保留来源目录结构；Flags 是辅助入口。支持按标题和路径搜索，选择文档后按需读取 Markdown，并提供阅读与原文模式。请求不能选择任意 Vault 文件或穿过链接目录。单文档读取上限为一 MiB，目录上限为 5,000 条。未增加记忆数据库、模型调用、导入或写入路由。

## 备选方案

获批的组合设计使用编号胶片卡片与暖色纸张阅读区。分类控件位于工作区上方；经历文件按文件名月份分组，无日期索引单独成组，长期事实按来源目录分组，交接按修改时间排序。数量表示文件数，包含索引。现有 API 已提供所需元数据，无需生成缩略图、提前读取所有文档或建立数据库。主标题为「记忆切片」，内部导航仍为「记忆」。窄屏将限高目录放在阅读区上方。局部 token 覆盖保证 Markdown 在浅色纸张上的可读性，不修改全局主题。

独立顶层插件页面不符合指定导航。第二份索引数据库会复制 Vault 并引入同步。修改 Bok 应用路由会增加供应商代码集成工作。现有所属插件和共享 Markdown 组件可以通过一个文件读取模块和一个内部视图完成需求。

## 验证与限制

用户随后澄清，胶片卡片应保留图像，而不是大编号方块。插件现打包三幅装饰性黑白场景，按来源路径固定分配，并叠加小角标编号。经过认证的图片路由只允许两个指定的 Memory 图片资源。更厚重的纸纹标题进一步贴近获批 mockup；不增加视图模式切换或额外来源扫描。

测试覆盖认证后的只读 HTTP 访问、路径越界及 junction 拒绝、分层目录、超大文档、标题搜索、原文阅读与刷新。浏览器验证覆盖实际构建页面、来源选择和响应式布局。仅索引当前 Vault Memory 目录；不包含目录外的归档月份或全文搜索。根 AGENTS.md 已记录用户要求，未来定制应减少上游耦合并优先选择合适的插件边界。
